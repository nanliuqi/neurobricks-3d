## 3. Windows 桌面开发前置环境

需要 Windows 10/11 x64、Node.js/npm、Rust MSVC 工具链、Visual Studio C++ Build Tools 与 Windows SDK、WebView2 Runtime。首次安装依赖及编译通常需要网络和足够的磁盘空间。

已记录的开发环境中 Rust 为 1.96.0，这是环境记录，不是新增的最低版本承诺。`src-tauri/target` 是编译生成的缓存，不应复制进 Git。

仅浏览器界面预览不需要 Python；fresh clone 后的真实训练需要自己的 Python 环境，不能借用作者机器的绝对路径。下面按现有构建脚本使用 64 位 Python 3.12。

## 4. Python 环境与能力探测

以下命令均在含 `package.json` 的源码根目录执行：

```powershell
py -3.12 -m venv .\src-tauri\sidecars\nb-trainer\.venv
.\src-tauri\sidecars\nb-trainer\.venv\Scripts\python.exe -m pip install -r .\src-tauri\sidecars\nb-trainer\requirements.txt
$env:NEUROBRICKS_PYTHON = (Resolve-Path .\src-tauri\sidecars\nb-trainer\.venv\Scripts\python.exe).Path
& $env:NEUROBRICKS_PYTHON -c "import torch, torchvision, numpy, pandas, PIL; print(torch.__version__); print(torch.cuda.is_available())"
'{"mode":"capabilities"}' | & $env:NEUROBRICKS_PYTHON -B .\src-tauri\sidecars\nb-trainer\main.py
```

没有 `py` 启动器时，用自己已安装的 Python 3.12 路径替换第一行的 `py -3.12`。虚拟环境创建成功后，其余命令不需要激活脚本。

[requirements.txt](../src-tauri/sidecars/nb-trainer/requirements.txt) 当前固定 torch 2.11.0+cu128、torchvision 0.26.0+cu128、numpy 1.26.4、pandas 2.2.3、pillow 11.3.0。CUDA/PyTorch 依赖可能占用数 GB，源码下载量小不代表训练环境安装量小。

能力输出应包含 `runtime_capabilities`；实际图像分类与 CSV 回归是否可用，以返回的能力和错误详情为准。`NEUROBRICKS_PYTHON` 用于 Rust 定位训练解释器，不会改变 PATH 中的 `python` 命令。

开发模式还会尝试项目 `.venv`、已激活环境、常见 Conda 路径、PATH 和已有训练器，但候选必须通过能力探测。显式指定并检查自己的环境通常更容易排错。

不要在新机器直接运行历史 `build.bat`、`upgrade-pytorch.bat`、`verify-gpu-support.bat` 或 sidecar 的 `install-dependencies.bat`：其中有作者本机路径或旧安装口径。它们被保留供历史参考，不是当前推荐启动入口。

## 5. 启动真实桌面程序与准备数据

确认执行过 `npm.cmd ci`，并在设置过 Python 变量的同一终端运行：

```powershell
npm.cmd run tauri -- dev
```

首次 Rust 编译可能较慢。浏览器预览与该命令一般不必同时运行；如果已有 Vite 进程占用端口，先结束自己启动的预览再尝试。不要强行结束不明进程。

设备必须明确选择。有兼容 NVIDIA 驱动及可用 CUDA 时才使用 GPU；没有时可以选择 CPU。若已选择的 CUDA 设备在启动时不可用，程序拒绝启动并要求重新检测／选择，不会静默改为 CPU。

Git 不保存 MNIST/CIFAR-10 数据文件。源码中的 `data/README.md` 仅保留资源目录与使用说明，不是数据集。首次内置数据训练会尝试下载到用户缓存并复用；需要能访问相应数据源的网络。离线使用须单独准备合法获取的数据，或导入自己的类别图像目录／CSV。

建议先用专用测试课题跑一次短训练：先确认数据、切分和预处理，再建立或选择匹配课题，添加并核对结构，设置参数，检查设备和训练前检查。CSV 回归必须明确目标列，不猜末列；旧课题与当前契约不匹配时应回到匹配配置或新建课题。

训练图的“如何读图”、对比区的“如何比较”和完成卡片的“结果说明”都是默认收起的静态解释。执行可信、严格可比、三值裁决和结论等级并非同一个概念；金标归属具体主张，PASS、FAIL、INCONCLUSIVE 不单独决定金标资格。

不要为了普通演示反复解封测试集。候选、冻结、解封与非严格对比仍须按既有确认和审计规则执行。

## 6. 自动化验证与证据边界

```powershell
npm.cmd run test:run
npm.cmd run typecheck
npm.cmd run build
cargo test --locked --manifest-path .\src-tauri\Cargo.toml
.\src-tauri\sidecars\nb-trainer\.venv\Scripts\python.exe -B -m unittest discover -s .\src-tauri\sidecars\nb-trainer\tests -p "test_*.py"
```

`npm.cmd run verify` 是前端、Rust、Python 测试与构建的组合入口。它通过 PATH 调用 `python`，不会读取 `NEUROBRICKS_PYTHON`；需先让 PATH 对应已安装依赖的环境。详见[测试指南](../TESTING.md)。

2026-10-24 的源码交付检查记录为：90 个前端测试文件／1383 项通过，生产代码类型检查通过。

2026-10-25 的仓库准备检查使用从 Git 暂存树导出的独立源码快照，另建 npm 缓存并按原锁文件执行 `npm.cmd ci`：90 个前端测试文件／1384 项、生产代码类型检查及 Vite 构建均通过。新增的一项测试检查源码包的数据资源占位与训练器构建规格是否齐全；数据资源配置改为直接引用目录，避免本机已下载的子目录掩盖纯源码检出时的资源匹配失败。

同一独立快照的 Rust 测试 29／29、Python unittest 14／14 通过。Rust 使用 `--locked --offline` 并复用本机编译缓存；Python 使用既有打包虚拟环境（Python 3.12.7、torch 2.11.0+cu128、pandas 2.2.3）。这些是同一开发机上的源码验证，不代表 fresh clone 无需下载依赖，也不等于真实 GPU 训练、干净机器运行、完整 `verify` 命令或完整应用打包已经通过。

`typecheck` 排除了 `src/__tests__`，不能据此声称测试文件也经 tsc 检查。已有 `<group>` DOM 测试警告与大 chunk 构建提示应如实区分。Playwright 尚未安装和接入门禁，仓库中的 E2E 文件只是待执行规格。

## 7. 后续重建完整应用

只评审源码或运行开发模式不需要执行本节。确需重建完整应用时，在准备好 Node、Rust 和 Python 3.12 后运行：

```powershell
npm.cmd run package:windows
```

脚本创建专用打包环境、安装锁定依赖、按已提交的 `nb-trainer.spec` 构建 PyInstaller 训练器并验证能力，再构建便携应用。这会消耗较多网络、时间和磁盘空间，不能将生成的依赖、运行时和应用直接加入源码仓库。

仅已存在并验证过训练器时才使用 `npm.cmd run package:windows:app-only`。fresh clone 不带训练器，直接执行生产 `tauri build` 可能因 `sidecar:verify` 失败；应准备前置环境，而不是删掉校验。完整应用是否可交付仍需针对生成包单独验收。

## 8. 常见排错与安全原则

- ENOENT/package.json：确认终端位于真正的项目根目录。
- Python 检测失败：先按第 4 节检查解释器、依赖导入和能力协议，再从同一终端启动。
- 数据下载失败：查看具体网络或路径错误；不要把占位文件视为数据，也不要拿浏览器模拟代替真实训练结果。
- Cargo 或 npm 下载失败：保留 `Cargo.lock`、`package-lock.json`，先检查网络与工具链，不先删除锁文件或无范围升级依赖。
- 页面和旧安装程序不同：先确认版本；旧 Release 和历史截图不代表本次源码的最新界面。
- 修改前建立自己的备份／分支。不要运行 `git reset --hard`、`git clean -fd` 或强制推送来“同步”一份尚未备份的工作树。
- 指标沿用现有严格序列，信任沿用协议投影；外部重跑不继承受控执行身份，非严格对比不能跳过确认、留痕与水印。
