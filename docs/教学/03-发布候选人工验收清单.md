# 03 发布候选人工验收清单

> **这是一份待执行清单，不是测试报告。** 本文档只描述"该怎么测、应当看到什么、失败时记什么"，**不声称任何一项已经通过**。执行人才是结果的唯一来源。

## 0. 使用说明

**结果取值（只能填这五种之一，空白等同"尚未执行"）：**

| 取值 | 含义 |
| --- | --- |
| 通过 | 前置条件成立且已实际执行，功能与关键提示符合预期；动态名称、计数及排版差异单独记录 |
| 失败 | 操作做完但表现与预期不符 → 必须写实际表现 |
| 未触发 | 前置条件不满足，本条根本没执行到（例如没有历史课题数据） |
| 受阻 | 被环境/版本/入口缺失挡住，无法执行本条 |
| 未测 | 执行到一半未得出结论，或有意留待后续 |

**硬性纪律**

1. 不允许把空白默认成"通过"，也不允许把"受阻"写成"通过"。
2. 一次执行只允许一份记录：编号、执行人、日期、被测构建（便携包 ZIP 名或 `git` 提交号/工作树标识）、系统分辨率与缩放、设备（GPU 型号 + 运行时自检里显示的 CUDA 状态）。
3. 记录错误**原文**（面板文字/弹窗文字/toast/错误面板），不要转述、不要修正错别字后粘贴。
4. 需要截图时**只描述截图内容并编号**，本仓库文档不收录截图、视频、权重或大数据文件。

**执行环境要求**

- 真实训练类条目（E / F / G / H / I 段）必须在**桌面运行时**执行：便携应用，或 `npm run tauri dev`。`npm run dev` 的浏览器模式是模拟数据，跑不出这些结论。
- 版本基线：本轮文案与新手引导改动**晚于** `NeuroBricks-3D-0.1.0-windows-x64-portable-20261013-182547`。用旧包执行 A / B / D 段会得到与"预期结果"不同的界面文字，那属于**版本不符 → 记「受阻」**，不是失败。

**先准备，再按段测试**

1. 备份需要保留的 `.nbproj`，使用专门验收课题，不清理或篡改真实档案。A–D 中的加层、删除、换位会改变结构；进入 E 段前重新确认空场景，只添加一次 LeNet-5。
2. E 段先选 MNIST，再添加模型；活动 Study 不匹配时，切到自由训练或新建匹配课题。EDU-024 留下完整训练，EDU-025 必须另起一次训练测试停止，不能把刚停止的运行用于 EDU-026。
3. F 段换 CSV 时不要沿用不匹配的图像 Study。准备数值 CSV（如 `x1,x2,y` 三列，每列均为有限数值，至少几十行并让 train/val/test 均有样本），另备一份带文本或日期列的 CSV 测 EDU-028。目标列显式选择 `y`；最终回归网络不得含卷积/池化，特征维度与输出 1 必须匹配。
4. G 段准备同一课题下至少两条真实完成、有完整验证指标的可比 Attempt；若需看趋势，至少 2 个 epoch。不能为了得到异组或不可信记录而手改 ledger。缺少相应历史材料时，EDU-031/032/036 如实记「未触发」或「受阻」。
5. I 段单独批准；没有专用封存数据与负责人许可就不执行解封。EDU-011 与 EDU-044 的并发部分没有自然人工入口，使用组件测试证据，不冒充已完成真机操作。

## 1. A 段 · 教学文案

#### EDU-001 层说明单一来源、无自相矛盾
- 前置条件：任一构建；右侧打开「帮助」。
- 具体操作：把帮助面板 `🧱 层类型说明` 区逐行与左侧「层组件库」卡片名称/说明对照；再打开右侧「参数」面板选中同类型积木，对照第三处描述。
- 预期结果：三处对同一层的名称与说法一致，**不存在**同一层的两套互相矛盾的解释；`🧱 层类型说明` 的条目应覆盖全部基础层类型（当前共 12 类）。
- 失败时记录：层类型、三处各自的原文、所在面板。

#### EDU-002 旧「快速开始」不与新引导重复
- 前置条件：含新手引导的构建。
- 具体操作：读帮助面板顶部区域，从上到下检查是否存在两份"从零开始怎么点"的路线。
- 预期结果：只有一条路线（「新手操作引导」折叠区）；不出现旧的"点击层组件卡片即自动加入场景"一类与新引导并存的重复段落。
- 失败时记录：两段文字各自的完整原文与顺序。

#### EDU-003 基础层添加手势与文案一致
- 前置条件：桌面或浏览器构建均可。
- 具体操作：在可清空的测试场景记下层数，单击一张基础层卡片并记录层数变化；再独立拖动一次并记录变化。对照帮助、新手引导、README 与层库提示，不从 `useDraggable` 名称猜测单击结果。
- 预期结果：一次有效添加只新增一层，按顺序追加到栈顶，不是场景内自由摆放；用户可见文案与实测手势一致。单击经拖拽事件完成添加并不自动构成 Bug；若文案承诺单击添加而实际不生效，或单次操作重复添加，则记「失败」。
- 失败时记录：单击/拖动前后层数、发生添加的具体手势、矛盾文案原文。完成后恢复测试结构。

#### EDU-004 快捷键表与真实按键一致
- 前置条件：场景中有 ≥3 块积木，且已点选一块。
- 具体操作：记录初始层顺序；点选中间一层测试 `↑`、`↓` 切换；重新选中后测试 `Shift+↑`，再 `Shift+↓` 移回。测试 `Escape` 后**重新点选一层**，按一次 `Delete` 并记录积木是否仍在；确认该积木仍是选中状态（若已取消请再点选一次），最后按 `Backspace`。不要在已取消选择时按删除并误判为快捷键失效。输入框聚焦时的行为由 EDU-013 单独验证，不在本条重复判定。
- 预期结果：切换选中/换位/取消选择/删除与帮助面板快捷键表逐条一致；表中删除项的按键列只写 `Backspace`，`Delete` 至多作为「未绑定」的说明出现。**`Delete` 按下去没有删除反应属预期行为，不记「失败」**；只有当表中又把 `Delete` 写成可用删除按键，或 `Backspace` 在已选中积木时没有删除，才记「失败」。
- 失败时记录：按键、期望、实际（含"无反应"），并记录按下时是否存在选中积木。

#### EDU-005 数据集/能力承诺文案不夸大
- 前置条件：任一构建。
- 具体操作：在帮助面板、README、层库提示中查找是否存在以下承诺：固定训练时长、"保证准确"、支持检测/分割/多标签/LLM 微调、Feature Map 可视化、Fashion-MNIST 数据入口、教学/专家双模式。
- 预期结果：不出现"几分钟一定完成"；不承诺未实现能力；不出现分割/检测/多标签承诺；预设说明里若提到 Fashion-MNIST，不能被读成"内置支持该数据集"。
- 失败时记录：文件/面板位置、原句、判断依据（哪里没有对应入口）。

## 2. B 段 · 新手引导与导航

#### EDU-006 引导只说明与导航，不动工程
- 前置条件：场景中已有 ≥2 块自定义积木；已选一个数据集；底部训练栏有非默认参数（例如 Epochs 改成 3）。
- 具体操作：打开「帮助」→ 展开新手引导 → **把 7 步里出现的每一个按钮都点一遍**（含全部导航按钮与折叠开关）。
- 预期结果：积木数量、积木参数、数据集选择、Epochs/Batch/高级参数、活动课题、候选选择、训练状态**全部保持原样**；只有右侧面板切换发生变化。
- 失败时记录：变化前后的具体项（层数、参数值、数据集名、课题名）。

#### EDU-007 七个步骤三要素齐全
- 前置条件：含引导的构建。
- 具体操作：逐步读 7 个步骤。
- 预期结果：每步都有「第 N 步：位置」「操作：…」「预期：…」三行，位置描述指向**界面上真实存在**的区域。
- 失败时记录：缺要素的步骤编号与原文。

#### EDU-008 导航目标都是真实右侧面板
- 前置条件：含引导的构建。
- 具体操作：记录引导里出现的所有导航按钮标签，逐个点击。
- 预期结果：每个按钮都切到对应右侧面板且面板正常渲染；按钮标签与活动栏面板名一致；**不存在**指向左侧模型库、底部训练栏或场景内按钮的"入口"（那两处按设计只给文字说明、不给按钮）。
- 失败时记录：按钮文字、点击后的实际面板或无反应。

#### EDU-009 导航沿用工作区偏好、不新增引导持久化
- 前置条件：右栏处于展开状态。
- 具体操作：从引导打开一个目标面板，再点活动栏「帮助」返回；重复至 3 个不同目标，再关闭并重启。记录重启前最后一个活动面板。
- 预期结果：足够宽的窗口下导航不主动收起右栏；窄窗口仍沿用自动收起规则。既有工作区导航会正常更新并恢复面板偏好，不能据此断言“完全不写存储”；只是没有新增引导进度或折叠状态持久化。存储键层面的结论另看组件测试，不靠重启现象推断。
- 失败时记录：收起/展开实际状态、重启前后的差异。

#### EDU-010 引导折叠不记录进度
- 前置条件：含引导的构建。
- 具体操作：折叠引导 → 切到「参数」面板 → 切回「帮助」→ 展开引导；再重启应用观察初始状态。
- 预期结果：折叠只影响当前视图，不出现"已完成第 N 步""进度 3/7"之类状态；步骤内容始终完整可读。
- 失败时记录：观察到的进度/完成标记原文；重启后折叠状态。

#### EDU-011 无回调退化（人工无法自然复现，转代码级验证）
- 前置条件：需要能构造"不传 `onNavigatePanel`"的渲染环境。
- 具体操作：正式界面中主布局总会注入导航回调，**没有自然人工入口**。请在开发环境用组件级渲染确认：不传回调时引导仍渲染 7 步文字且**不渲染**任何导航按钮。
- 预期结果：文字完整可读、按钮不出现、无控制台错误。
- 失败时记录：渲染方式、缺失文字或多余按钮。
- 说明：本条在纯人工验收下应记「受阻」，不要凭"看起来没问题"填「通过」。

#### EDU-012 引导边界声明文字在场
- 前置条件：含引导的构建。
- 具体操作：读引导开头提示与末尾说明。
- 预期结果：能看到"本模块只增加操作说明和导航，不会自动配置工程""这只是演示顺序，不构成任何结论"这类边界声明，以及"预设追加不清空/不替换现有结构"的说明。
- 失败时记录：缺失的声明项。

#### EDU-013 帮助面板不劫持输入
- 前置条件：场景有选中积木；另有可输入控件（如底部 `Epochs` 输入框）。
- 具体操作：把焦点放进输入框，按 `↑`、`↓`、`Backspace`、`Escape`。
- 预期结果：输入框正常编辑数字/文本，场景不删除积木、不切换选中。
- 失败时记录：焦点所在控件、按键、被误触发的场景动作。

## 3. C 段 · 已有工程保护

#### EDU-014 经典模型是追加不是替换
- 前置条件：场景已有手工搭的 ≥2 块积木（非任何预设）。
- 具体操作：展开「经典模型」→ 点 LeNet-5 卡片 `+ 添加`。
- 预期结果：原有积木**一块不少**地保留，预设层追加在栈顶；不出现静默清空。
- 失败时记录：添加前层数与前两块名称/参数，添加后完整层清单。

#### EDU-015 清除场景必须走确认，取消无损
- 前置条件：场景有积木。
- 具体操作：点 `🗑️ 清除` → 在确认框点**取消**；再次点清除 → 点**确认**。
- 预期结果：取消后积木一块不动；确认才清空。确认框应显示会影响的数量或明确后果。
- 失败时记录：确认框原文、取消后积木数、是否绕过确认。

#### EDU-016 数据集切换不偷改结构、适配要经确认
- 前置条件：已用 MNIST 搭好一个图像网络。
- 具体操作：记录 MNIST 网络的 Input 形状与首个卷积通道参数，然后改选 CIFAR-10，使现有网络的输入确实不匹配；对数据集面板给出的适配确认先取消，再重新触发并确认。
- 预期结果：数据集选择可以立即改变，但**现有层参数**仅在确认后改变；确认框展示改动摘要与原因，取消不改层。此条不是测新增经典模型（新增预设会适配后直接追加）；CSV 含卷积时可能只提示改用全连接，不保证弹出适配框。
- 失败时记录：确认框标题与正文原文、取消后的实际层参数变化。

#### EDU-017 清除数据集会连带清除列选择（须明示）
- 前置条件：已导入 CSV 并确认了目标列与切分字段。
- 具体操作：点 `清除当前数据集`，读确认框，选择取消；再执行一次并确认。
- 预期结果：确认框明确说明将清除与该数据集关联的目标列和切分字段选择；确认后这些选择真的被清空且不残留旧选中。
- 失败时记录：确认框原文、清除后残留的字段值。

## 4. D 段 · 键盘、窄面板与显示环境

#### EDU-018 键盘可达引导全部控件
- 前置条件：只用键盘，不碰鼠标。
- 具体操作：`Tab` 进入帮助面板 → 到达引导折叠开关 → 展开 → `Tab` 到每个导航按钮 → `Enter` 激活。**再走左侧模型库这条新手路线**：`Tab` 到「层组件库」总标题 → 用 `Enter` 收起、`Space` 展开（记录 `▼/▶` 指示与 `aria-expanded` 是否随之变化）→ `Tab` 到「经典模型」小节标题 → 展开 → 继续 `Tab` 逐个到达各预设卡片右下角的 `+ 添加` 按钮 → 选中其中一个按 `Enter`，记录场景新增层数；再选另一个按 `Space`，再记录一次。全程观察焦点是否可见、是否丢失或跳回页面顶部，以及是否误触发清除、训练等其他操作。
- 预期结果：引导的折叠开关与全部导航按钮可聚焦、焦点环可见、`Enter` 与点击等效；折叠开关的展开/收起状态对读屏可感知（`aria-expanded` 生效）。「层组件库」总标题与「经典模型」小节标题都可键盘展开收起，`aria-expanded` 与实际显示始终一致；每个预设的 `+ 添加` 都能用键盘到达并按下，可访问名称包含模型名（例如「添加 LeNet-5 预设」），8 个预设的名称互不相同；**一次激活只添加一套预设**（第二次激活后的层数只增加该预设自己那份层数，不翻倍）；折叠后区内不应残留可聚焦的隐藏控件。任一环节无法聚焦、焦点环不可见、一次按键执行两次或误触发别的动作，本条记「失败」并注明具体元素与按键。
- 失败时记录：无法聚焦或重复触发的元素顺序、按键、激活后场景实际新增的层数与被误触发的动作。

#### EDU-019 窄面板不横向溢出
- 前置条件：用 1280×720 起步，右栏仍能保持展开；把右栏拉到合法最小宽度（当前 260px）。
- 具体操作：展开引导，检查长句与按钮换行；再逐渐缩窄整个窗口，另行观察自动收起。若已自动收起，应先增大窗口再打开帮助，不在隐藏面板上测排版。
- 预期结果：中文长句在面板内换行、不出现横向滚动条、按钮文字不被截成省略号、面板标题栏仍可见。
- 失败时记录：窗口宽度像素、哪个步骤/按钮溢出、溢出表现。

#### EDU-020 125% 缩放下可读
- 前置条件：Windows 显示缩放设为 125%。
- 具体操作：完整走一遍引导 7 步 + 帮助面板其余四个说明区（`⌨️ 键盘快捷键`、`🧱 层类型说明`、`📖 结果怎么读`、`❓ 常见问题`）。
- 预期结果：文字不重叠、不裁切，折叠开关与按钮仍可点，右栏不需要横向滚动。
- 失败时记录：分辨率+缩放组合、异常区域截图编号（截图不进仓库）。

#### EDU-021 150% 缩放下可读
- 前置条件：Windows 显示缩放设为 150%。
- 具体操作：重复 EDU-020。
- 预期结果：同 EDU-020；额外确认底部训练栏与场景左上角按钮仍可达。
- 失败时记录：同 EDU-020 格式，并注明是否与训练栏/场景控件冲突。

#### EDU-022 折叠开关在小字号下仍可用
- 前置条件：任一 DPI 设置。
- 具体操作：连续点折叠开关 5 次。
- 预期结果：状态切换正确、无内容错乱、无残留渲染；每次展开都是完整 7 步。
- 失败时记录：第几次开始出现异常、异常表现。

## 5. E 段 · 图像训练与推理

#### EDU-023 训练前检查能拦住并定位
- 前置条件：桌面运行时；数据集已选 MNIST；场景留一个会失败的配置（例如最后一个 Linear 输出改成 8）。
- 具体操作：点 `🚀 开始训练`。
- 预期结果：训练**不启动**；检查面板自动展开并聚焦第一条阻断项；标题与详情可在界面读到（形如 `输出层与数据任务不匹配` + `MNIST 有 10 个类别，需要最后一个 Linear 层输出 10 个类别分数`）；右栏底部 `校验结果` 区同时给出错误条数与对应层，选中该层时参数面板显示 `⚠ 错误`。
- 失败时记录：是否启动、阻断项标题/详情原文。

#### EDU-024 真实训练跑通且设备留档一致
- 前置条件：桌面运行时；MNIST + LeNet-5；Epochs 设 1（仅验收用）。
- 具体操作：开始训练到完成，记录「设备」面板显示的设备与运行时 CUDA 状态。
- 预期结果：训练完成；曲线与日志有真实数据；不留"看起来完整但没完成"的状态；不给出任何时长承诺。若选中 CUDA 而运行时不再报告可用，则应拒绝启动并给出"设备留档与实际执行不一致"的解释文案。
- 失败时记录：设备名、CUDA 状态、错误面板原文、停在第几 epoch。

#### EDU-025 暂停/恢复/停止行为可预期
- 前置条件：EDU-024 已完成；**另启动一次**用于控制测试的训练，使用能来得及操作的轮数（如 5）。若仍瞬间结束则记「未触发」，不要改写完成运行的状态。
- 具体操作：运行中 `暂停` → 观察 → `恢复` → `停止`；等停止完成，再点 `清除运行态提示`。
- 预期结果：按钮态如实反映状态（停止中为 `正在停止…`）；停止的 Attempt 不冒充 completed 或严格候选。重置会清当前会话指标/结果视图，不只是文字；EDU-024 的已留档历史证据不应删除。部分曲线只作排障用途。
- 失败时记录：每步按钮可用/禁用状态与实际表现。

#### EDU-026 图像推理可用且口径正确
- 前置条件：EDU-024 已完成并生成模型卡片。
- 具体操作：使用 EDU-024 **已完成**运行的卡片（不是 EDU-025 已停止运行）→ `📷 选择图片` → `🚀 开始预测`，注明图片来源。缺卡片/未选卡片是另一个条件分支，有自然场景才另测，不删除历史权重来造空态。
- 预期结果：返回类别与 `置信度: …%`、`Top-5 概率分布`；这些是分类输出，不证明概率校准或泛化。另测空态时，未选卡片应提示先选择、确无产物才显示 `暂无可用模型`，不伪造结果。
- 失败时记录：模型卡片标识、输入图、原始输出文字。

## 6. F 段 · CSV 回归

#### EDU-027 目标列纪律（不默认取末列）
- 前置条件：桌面运行时；自备一份含 ≥2 个数值特征列 + 1 个目标列的 CSV。
- 具体操作：导入 CSV，**故意不选目标列**，直接搭一个最后的 Linear 输出为 1 的全连接网络，点开始训练。
- 预期结果：目标列下拉占位为"不会默认取末列"；不选目标列时训练被阻断（`CSV 目标列未确认`）。
- 失败时记录：阻断项标题/详情；若被放行则记「失败」并写出实际使用的目标列。

#### EDU-028 非数值列被明确拦下
- 前置条件：另一份 CSV 含数值目标和一列文本或日期；目标已显式确认，切分为 random，文本/日期列尚未排除。
- 具体操作：把该列留在特征中，尝试训练；记录拦截后，再按业务含义决定编码或选作真实 group/time 字段，不能只为消除提示而随意声明。
- 预期结果：给出 `CSV 特征列含非数值列` 类阻断，并说明怎么处理（选为 group/time 切分字段，或先在源数据完成数值编码）。
- 失败时记录：列名、阻断原文。

#### EDU-029 表格回归端到端
- 前置条件：回到 EDU-027 的纯数值 CSV，明确选择目标 `y`；空场景添加 MLP，或按数据集面板确认适配现有全连接网络；核对 Input 特征数、无卷积/池化、末层输出 1、Study 契约匹配。Epochs 设 1。
- 具体操作：确认训练前无阻断 → 训练完成 →「推理」面板选中本次回归卡片 → 按训练时特征顺序输入原始数值 → `🚀 计算回归预测值`。
- 预期结果：输入形状按当前配置推导（例如 2 个特征 → `1×1×2`）；输出单一预测值；训练与推理复用同一套标准化口径（推理面板应体现复用训练集参数）。
- 失败时记录：特征顺序、输入值、输出值、任何形状相关提示原文。

## 7. G 段 · 严格对比与结论边界

#### EDU-030 严格分组口径如实呈现
- 前置条件：桌面运行时；同一活动课题下已有 ≥2 条受控完成记录（同数据集、同切分口径）。
- 具体操作：「课题」→ `证据对比与主张` → 看「严格实验对比」分组与共同指标下拉。
- 预期结果：可比记录进入 `严格可比组 N`；口径不同的记录不混入同一组；分组说明为"按数据、切分、任务、预处理与指标语义分组；结构/超参/轮数差异不阻止比较"。
- 失败时记录：各 Attempt 标识、被分到哪组、差异点。

#### EDU-031 不可信执行不得进入严格对比
- 前置条件：存在一条受控管线之外完成的"已完成"记录。
- 具体操作：尝试把它勾选进对比。
- 预期结果：它被单独列在"已完成但执行不可信（不得进入严格对比）"区且禁用；悬停说明为受控管线之外的结果不能作为严格对比证据；未完成的部分曲线只作为排障用途，明确不进入严格完成组、不参与候选排名、不生成最终性能结论。
- 失败时记录：该记录身份、是否可勾选、实际曲线是否出现。

#### EDU-032 非严格对比：确认、留痕、强制水印
- 前置条件：当前课题**已有**两条可选择但严格键不同、指标仍可共同展示的真实历史记录；审计健康。正常训练会拒绝与活动 Study 不匹配的配置，不要为本条绕过它，也不要把其他 Study 的记录串进来。没有现成材料就记「未触发」；边界行为由 ComparisonView 组件测试补充。
- 具体操作：在同一课题勾选该异组 Attempt 集合 → 点击当前界面的“仍然显示（带水印）”类入口 → 先取消确认，检查未授权展示；重新发起，再确认。
- 预期结果：必须经过 `确认进行非严格对比？`；确认后曲线与报告**强制带** `非严格可比` 水印，留痕只作用于那组精确 Attempt；界面应说明只有审计事件成功持久化后才展示非严格曲线；toast/记录里"水印会进入导出报告"要有据可查。
- 失败时记录：完整 Attempt 集合、确认框原文、取消后表现、水印是否出现在曲线与 Study 报告（见 EDU-037）。

#### EDU-033 单 seed 不允许被读成"稳定提升"
- 前置条件：选择单一 seed 的至少两条严格指标记录；多 seed 未配对另作条件分支，不期待所有对比都显示同一徽章。
- 具体操作：读方差资格徽章与最终指标表。
- 预期结果：单 seed 显示 `未验证方差（单 seed）` 并写明不能据此声称显著/稳定/可靠；表里 seed 列若未固定要显示"未固定"；多 seed 未配对不能被表述为方差已验证。
- 失败时记录：徽章标签原文、说明文字、seed 列实际显示。

#### EDU-034 封存测试集不被自动访问
- 前置条件：桌面运行时；不要点击任何解封类按钮。
- 具体操作：完成若干次训练、做对比、生成报告草案（只到确认前一步），全程观察是否出现 eval-only / 解封记录。
- 预期结果：没有因训练、浏览或报告操作而自动申请封存评估的事件。界面若提供审计明细，可核对执行前后；仅“没看到提示”不足以证明无访问，没有可查证据时记「受阻」，不得据此填通过。不要为检查而打开封存样本或修改审计文件。
- 失败时记录：时间、触发动作、新增审计事件原文（本条一旦失败属于严重问题，立即停止后续 G/I 段并上报）。

## 8. H 段 · 导出与重启持久化

#### EDU-035 导出项门控
- 前置条件：新工程，未做过真实训练。
- 具体操作：打开「导出」面板，观察权重、完整模型、NumPy 权重、训练日志、实验复现包各项。
- 预期结果：不满足条件的项禁用并给出原因，不产生空文件或半成品。代码导出也可能要求存在网络层；有合法结构且无需训练时应可导出，不能在空场景要求所有代码按钮启用。

#### EDU-036 复现包拒绝伪复现

- 具体操作：对它们分别尝试 `导出实验复现包`。
- 预期结果：被拒绝，并给出"缺少原始权重或冻结预处理协议""没有独立验证集，导出脚本将触碰封存测试集，已拒绝生成伪复现实验包"这类原文；不生成会触碰封存集的脚本包。

#### EDU-037 导出保留可信等级、外部重跑不继承身份
- 前置条件：有可导出的受控 Attempt；若要检查越界水印，EDU-032 的精确集合已成功留痕；没有该材料时只测普通来源标签，并注明水印分支未触发。

- 预期结果：两类导出都不把外部重跑授予受控身份。**Study 报告**列出非严格事件、精确 Attempt 集合和水印说明；**单 Attempt 实验包**不等同于多曲线对比报告，不要求复制 Study 的所有越界标记，也不得伪称承载了整组对比结论。有效等级与当前审计/Claim 投影一致，不把导出动作当作升级资格。
- 失败时记录：文件相对名、缺失的标签/水印。

#### EDU-038 重启后证据持久、演示态不持久
- 前置条件：已完成真实训练并有课题记录；非空结构已保存为 `.nbproj` 备份，并保持至少 30 秒让现有自动保存有机会执行；引导处于折叠状态。
- 具体操作：记录 Study/Attempt 身份和活动面板 → 完全退出 → 在同一 Windows 用户下重启；若出现“是否恢复”提示，明确选择恢复并记录选择。再打开对应课题和帮助。
- 预期结果：档案记录仍在且历史曲线可查，数据集按原有机制恢复；结构遵循自动保存恢复提示，而非承诺无条件自动重现，备份可用于兜底。引导重新挂载时默认展开；工作区偏好仍可正常持久化，没有新增引导进度键。
- 失败时记录：丢失的记录类型与数量、重启后引导状态、面板偏好实际值。

#### EDU-039 归档不物理删除且受运行态约束
- 前置条件：有一个课题含已归档候选或可归档记录；另有一个课题存在运行中/暂停的 Attempt。
- 具体操作：先归档无运行态的课题；再对运行中的课题点归档。
- 预期结果：归档后证据仍被保留（列表可见"已归档 N 个课题，证据仍被保留"）；运行中的课题归档被运行时拒绝并说明原因；不误删历史。
- 失败时记录：课题标识、拒绝原文、记录是否仍可查。

## 9. I 段 · 候选、冻结、解封等关键确认步骤

> **本段有不可逆动作。** 执行前记录专用验收 Study、封存测试集身份、已有解封序号、负责人许可与允许的评估次数。次数属于该测试集全局历史，不因换 Study、重命名或同池重划清零。
> 第一次解封只是金标的必要条件之一，还须满足执行、契约、机器检查、冻结主张与审计等条件。许可事件先落盘，再发起 eval-only；许可已落盘后即使进程未成功启动或结果未采信，也不能删事件或承诺资格恢复。取消**尚未确认的**弹窗不会访问封存集；已授权同一 Claim 的重试沿用既定序号，不是购买一条新金标主张。

#### EDU-040 候选锁定与撤回规则
- 前置条件：专门验收课题，`candidate_selection` 类型，已留痕选定一个候选权重。
- 具体操作：先尝试撤回/更换候选；再让该候选被评估主张引用后重复尝试。
- 预期结果：未被引用时可按原有流程撤回/更换；被引用后界面明确显示"当前候选已被评估主张引用，不能撤回或更换。需要验证其他权重时请新建 Study"，且入口确实不可操作。
- 失败时记录：候选序号、引用状态、是否仍可改动（若能改动记「失败」并立即停止）。

#### EDU-041 冻结主张需要显式确认并留痕
- 前置条件：桌面运行时（**浏览器模式本条应记「受阻」**，见 EDU-043）；已有可冻结的主张草稿。
- 具体操作：在 `冻结评估主张` 区先 `保存草稿`，再点 `冻结主张` → 读确认框 → 确认；随后查审计链。
- 预期结果：`冻结主张` 只在审计可写、候选绑定就绪时可点；必须经过 `确认冻结这条评估主张？`（确认按钮为"确认冻结"）；取消不写入；确认后冻结内容与草稿一致，审计链出现对应只追加事件。
- 失败时记录：确认框原文、审计事件编号/内容、是否出现"未确认即冻结"。

#### EDU-042 裁决前必须确认继续（不可逆告知）
- 前置条件：EDU-041 已完成冻结；负责人已批准消耗封存集资格。
- 具体操作：在已冻结、尚未授权的主张卡找到解封入口，抄录实际标签 → 打开告知 → **先取消**，检查无新增解封授权；再次打开，经批准才确认一次。没有再次解封许可时，不为验证序号而多评估一次。
- 预期结果：取消未授权请求不访问封存集；确认告知不可逆风险，成功持久化许可后才可进入 eval-only。许可/评估/裁决分别如实留痕；已有历史的记录按测试集全局次数显示，第 1 次仍不自动保证金标。若授权后失败，只记录实际状态，不能一概判为“资格未消耗”。同一 Claim 已授权重试应走既定裁决，不新建主张冒充首次解封。
- 失败时记录：确认框原文、取消后是否仍出现访问痕迹、解封序号显示。
- 风险提示：**误点确认即不可回收**，本条只允许在已获批准的一次性验收课题上执行。

#### EDU-043 审计不可写时失败关闭，不提供越界入口
- 前置条件：`npm run dev` 浏览器模式（或后端未就绪的桌面状态）；主张区域已可见。若还无合法候选或草稿条件，明确记录，不能伪造可信记录来补条件。
- 具体操作：观察 `冻结评估主张` 区的提示与按钮态；有合法绑定条件时另测 `保存草稿`，缺条件则标注该分支未触发。
- 预期结果：审计不可用时应显示失败关闭提示，`冻结主张` 禁用且无“跳过审计继续”入口。草稿操作不以审计健康为唯一条件：候选绑定就绪、其他操作条件满足时才允许保存；无候选时保存也可禁用。草稿本地保存不代表只追加审计已持久化。浏览器界面应说明无法写入桌面审计。
- 失败时记录：实际提示、`冻结主张`/`保存草稿` 各自的可用状态、是否存在可绕过的按钮（存在则记「失败」并停止）。

#### EDU-044 导出降级确认针对冻结快照
- 前置条件：专用测试档案自然出现降级状态，或开发环境已有组件测试夹具；**不得破坏真实审计来构造条件**。
- 具体操作：人工可在自然降级时点报告导出并选保存目录，先取消，再重新发起后确认，检查标记。弹窗是模态框，正常界面不能直接点击背后的课题选择器；“确认期间 Study 切换/审计恢复/新增证据”应运行 `StudyReportExport.test.tsx` 的并发测试，不要求测试人穿透弹窗或用 DevTools 改生产 store。
- 预期结果：取消不写报告；确认写请求时冻结的降级快照并保留不完整标记。组件级并发场景中，Study 身份变化使请求作废，同一 Study 新证据或审计恢复不能静默替换快照。人工未自然触发时记「未触发」或「受阻」，备注组件证据与人工结果分别记录。
- 失败时记录：构建、自然触发条件、确认框原文、导出标记；组件验证另记命令与测试用例结果，不能冒充真机已测。
