## 1. 两种使用方式

### 1.1 便携应用（推荐给课堂、推荐给提交作品的人）

1. 拿到 `NeuroBricks-3D-x.x.x-windows-x64-portable-*.zip`（连同 `.zip.sha256`）。
2. **完整解压 ZIP 到一个目录**，然后双击其中的 `NeuroBricks 3D.exe`。
3. 首次启动会自检内置训练运行时，等待它完成即可（时间取决于磁盘与设备，不给出固定秒数）。

必须知道的约束：

- **不能只把 EXE 拷出来单独运行。** 保持整包目录不变：EXE 同级有 `sidecars`，其下的 `nb-trainer` 与 `dist/nb-trainer` 是两条不同路径；冻结训练器位于 `sidecars/dist/nb-trainer/nb-trainer.exe`，旁边的 `_internal` 也必须保留。
- 建议解压到**层级不深的短路径目录**，并预留 **≥12 GB 可用空间**。
- 2026-10-13 完整便携包内置 Python 3.12.7、PyTorch 2.11.0+cu128、TorchVision、表格回归依赖、CUDA 用户态运行时，以及 MNIST / CIFAR-10 数据。之后的新包须核对随包清单与设备自检，不能仅凭版本号 `0.1.0` 推定包含同一套运行时。
- 因此便携包用户**不需要**安装 Python、Node.js、Rust、Anaconda 或 CUDA Toolkit。
- **需要的系统条件**：Windows 10/11 64 位；**WebView2 Runtime**（Tauri v1 依赖系统 WebView，缺失时应用起不来或窗口无法显示；请按应用包内的 `00-启动说明.md` 从微软官方渠道补装后重试）；想用 GPU 训练则需要**兼容的 NVIDIA 显卡驱动**。
- 没有兼容 GPU/驱动时，应用仍会列出 CPU 设备；实际是否用 GPU 由「设备」面板的自检结果决定（见 6.5）。
- 当前已交付旧包**未做代码签名**，新包以发布说明为准。首次运行可能出现 SmartScreen 提示；企业环境的安全策略也可能直接拦截。遇到拦截请走公司审批流程，**不要为了运行它而关闭杀毒软件或端点防护**。
- 训练产物、实验档案写入**当前 Windows 用户的数据目录**，不会写进应用包所在目录。
- 包内不含任何开发者的个人课题（Study）、评估主张（Claim）、SSH 凭据或私有权重。

### 1.2 开发模式（改代码的人）

前置：准备符合项目依赖要求的 Node.js 与已安装的项目依赖；桌面开发另需 Rust、Windows C++ 构建工具与 WebView2。真实训练还必须有**通过能力自检的 Python/PyTorch 环境，或项目可找到的完整冻结 sidecar**；没有后者时，不能以为桌面开发不需要 Python。重新构建发布 sidecar 按仓库构建说明准备 64 位 Python 3.12。

先在终端切换到含 `package.json` 的**当前源码根目录**，确认开发依赖已安装，再执行下列命令。Windows PowerShell 若拦截 `npm.ps1`，可使用等价的 `npm.cmd`，无需降低系统执行策略。下列作用与当前 `package.json` 一致：

| 命令 | 实际作用 |
| --- | --- |
| `npm run dev` | 只起 Vite，浏览器里看 UI。**不启动 Python**，见下方"演示模式"提醒 |
| `npm run tauri dev` | 桌面开发运行，会探测可用训练运行时并启动真实训练路径 |
| `npm run build` | `tsc && vite build` |
| `npm run preview` | `vite preview` |
| `npm run test` | `vitest`（watch） |
| `npm run test:run` | `vitest run`（一次性跑前端测试） |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run test:rust` | `cargo test --manifest-path src-tauri/Cargo.toml` |
| `npm run test:python` | sidecar 的 `unittest discover` |
| `npm run verify` | 依次 `test:run` → `test:rust` → `test:python` → `build` |
| `npm run sidecar:build:windows` / `sidecar:verify` | 构建 / 仅校验发布 sidecar |
| `npm run package:windows` | 先重建并校验 sidecar，再产出 Windows 便携包 |
| `npm run package:windows:app-only` | 跳过 sidecar 重建；打包前仍须确保有匹配、完整的 sidecar，不能据此认定新源码已配上新训练器 |

`npm run tauri dev` 探测训练运行时的顺序：`NEUROBRICKS_PYTHON` → 项目/已激活环境 → 常见 Conda 路径 → PATH → 已存在的内置 sidecar；每个候选必须通过能力协议才会被采用。

**`npm run dev` 的浏览器演示模式有一个必须知道的陷阱**，界面上有两处信号：

- 训练前检查会给出警告项 `浏览器演示模式`，详情是 *浏览器模拟不会产生可信执行证明，不代表受控可信训练；不阻止本次启动。*
- 训练一旦开始，日志里会出现一行 warn：
  > 浏览器演示模式：以下 Loss/Accuracy 为模拟数据，不会生成模型或权重。

也就是说浏览器里曲线确实在动（警告级别，不阻止启动），但**没有真实模型**：推理面板拿不到可推理的产物，权重类导出也不可用（导出训练日志同样被拦，悬停说明为 `浏览器演示指标不可作为真实实验数据导出`）。同时，课题主张的冻结/解封在浏览器模式下会**失败关闭**（见 9.3）。要做真实训练与推理，请用 `npm run tauri dev` 或便携应用。

## 2. 界面分区：第一次打开先看哪里

| 区域 | 内容 |
| --- | --- |
| 左侧 | **层组件库**：基础层卡片与「经典模型」小节；经典模型默认收起，点标题展开 |
| 中间上方 | **3D 场景**，左上角三个按钮：`🔓 视角自由` / `🔒 视角已锁定`、`🔄 复位`、`🗑️ 清除` |
| 中间下方 | **底部训练栏**：数据集只读格子、Epochs、Batch、`⚙ 高级`、`🚀 开始训练`、训练前检查面板 |
| 最右侧活动栏 | 面板切换：**参数 · 数据集 · 课题 · 导出 · 设备 · 训练监控 · 云端训练 · 推理 · 代码 · 帮助** |
| 右栏底部（常驻） | `校验结果` 区：列出结构错误与数据契约错误，并给出错误条数；不随面板切换消失 |
| 帮助面板 | `🚀 快速开始` 小节里就是**新手操作引导**（可折叠，7 步）：*本模块只增加操作说明和导航，不会自动配置工程*；其后依次是 `⌨️ 键盘快捷键`、`🧱 层类型说明`、`📖 结果怎么读`、`❓ 常见问题` |

三个容易误解的点：

- 场景左上角的「视角自由 / 视角已锁定」**只控制旋转、平移和缩放，不锁定积木编辑**。
- 引导里的导航按钮**只切换右侧面板内容，不会主动收起右栏**；窗口过窄时仍沿用自动收起规则。要回到引导，再点活动栏的「帮助」即可。
- 导航按钮**不记录进度、不改变工程**：它只调用工作区已有的面板展开动作。折叠与否只保留在当前视图，不写入持久化设置。

## 3. 选数据

全部在右侧「**数据集**」面板完成。

- **内置数据集**：`内置数据集` 下拉（占位是 `请选择…`），只有 **MNIST** 与 **CIFAR-10** 两项。选完后底部训练栏的「数据集」格子会从红色 `未选择` 变成所选名称。
- **图像分类自定义数据**：`选择图像文件夹`。导入过程会显示阶段文字（`正在选择图片目录…` / `正在导入图片数据集…`），期间所有导入入口禁用。
- **表格回归**：`选择 CSV 文件`（`正在选择 CSV 文件…` / `正在导入 CSV…`）。
- **Excel**：面板里有 `选择 Excel 文件` 按钮，但它**只用于说明边界**，不会打开文件选择器、也不会调用导入命令。要跑表格数据请先导出成 CSV。
- **清除当前数据集**：会弹出确认框，明确写「将清除与该数据集关联的目标列和切分字段选择」。这是有意设计，不要绕过。

CSV 还要在同一个面板里再确认两件事：

1. **回归目标列（必须确认）**：下拉占位是 `请选择目标列（不会默认取末列）`。没确认前不允许训练，避免把普通特征静默当标签。
2. **切分策略**：内置数据集可用 `官方预定义 train/test 切分`；自定义数据是 `固定 seed 随机切分`，CSV 还可按时间先后（需要真实时间字段）或按 group 字段分组。面板会提示 *temporal 仅在 CSV 存在真实时间字段时开放；文件修改时间不代表业务时间，不用于可信切分。*

## 4. 搭模型 / 添加经典模型

- **单个层**：通过左侧基础层卡片添加，新增层按顺序追加到栈顶，不是在场景里自由摆放。源码采用拖拽事件完成添加，但这不足以证明“普通单击一定不添加”或“必须放到指定落点”；实际手势需按 EDU-003 在当前桌面构建确认。首次上手直接走下一条已明确的预设入口，不依赖这项手势判断。
- **经典模型预设**：展开左侧「经典模型」小节 → 点卡片上的 **`+ 添加`**。
- 添加预设的语义是**追加**：预设的层加到已有积木栈的顶部，**不会清空或替换你现有的结构**。左侧原文提示：
  > 💡 添加模型时会自动适配当前数据集（Input 形状、卷积通道数、全连接特征数）。
- 想让预设从干净状态开始？有需保留的结构先用现有 `.nbproj` 保存入口备份，再点场景左上角 `🗑️ 清除` 并在确认框里确认，最后只添加一次预设。**这是破坏性操作**；不要把再次追加预设当作修复或撤销。
- 形状不匹配时分工是这样的：选中积木后，「参数」面板顶部给出该层的 `⚠ 错误 / ✓ 正常` 状态标记；**具体的期望值与实际值、修复建议**出现在右栏底部 `校验结果` 区和训练前检查的详情里。红色连接线表示当前形状链走不通。

## 5. 参数在哪里改

| 想改什么 | 在哪里 |
| --- | --- |
| 某一层的超参数（通道、核大小、神经元数、dropout 比例等） | **先点选场景里的那块积木**，再看右侧「**参数**」面板 |
| 整网概览（未选中任何积木时） | 右侧「参数」面板位置会显示整体统计 |
| Epochs / Batch / 优化器 / 学习率 / seed / weight decay / 验证集比例 | **底部训练栏**：`Epochs`、`Batch`，其余在 `⚙ 高级` 里；初始默认 Epochs=5、Batch=32、seed=42，但已有工程可能恢复上次配置，操作前以当前值为准；`~N秒/epoch（粗略估计）` 不是时长承诺 |
| 用哪个设备跑 | 右侧「**设备**」面板（见 6.5） |
| 当前网络对应的 PyTorch 代码 | 右侧「**代码**」面板，可复制 |

选中积木后可用键盘操作，场景内提示原文：

> ↑↓ 切换选中 · Shift+↑↓ 换位 · Backspace 删除 · Escape 取消选择

注意：**删除只绑定了 `Backspace`**，按 `Delete` 不会删除积木，帮助面板的快捷键表同样写明这一点。输入框、下拉、文本域以及任何可编辑区域聚焦时，场景的上述快捷键一律不生效、按键原样交还给正在编辑的控件——所以在名称里退格不会误删积木，想用 `Backspace` 删除积木得先点选场景中的那块积木。

## 6. 训练

### 6.1 先过"训练前检查"

底部训练栏内嵌**训练前检查**面板。它会实时列出阻断项（blocker）与提醒项（warning）。点 `🚀 开始训练` 时如果存在阻断项，**训练不会启动**，面板会自动展开并聚焦第一条阻断项。

常见阻断项（标题即界面原文）：

- `正在检查训练运行环境` —— 自检还没结束，等它完成
- `训练运行时不可用` —— 到「设备」面板重新检测
- `尚未导入数据` —— 回「数据集」面板选择或导入
- `没有网络层` —— 先加积木或添加经典模型
- `Epochs 无效`（必须是 1–50 的整数）、`Batch 无效`、`学习率无效`、`Weight Decay 无效`、`验证集比例无效`
- `CSV 目标列未确认` / `CSV 目标列非数值` / `CSV 特征列含非数值列` / `CSV 没有可训练特征`
- `CSV 输入特征数与 Input 声明不一致` / `CSV 不支持卷积/池化层` / `CSV 回归输出必须为单值`
- `网络结构存在形状错误` / `输出层与数据任务不匹配`
- `Excel 暂不可训练`（当前训练后端不支持 Excel，需先转 CSV）

另有**提醒项（warning，不阻止本次启动）**，界面上与阻断项分列，别把它们读成"不能训练"：

- `浏览器演示模式` —— *浏览器模拟不会产生可信执行证明，不代表受控可信训练；不阻止本次启动。*
- `审计持久化降级` —— *只追加审计链尚未恢复健康；训练可能运行，但档案完整性不能背书。不阻止本次启动。*
- `结构校验警告` —— 逐条列出既有校验给出的警告原文

### 6.2 启动与等待

`🚀 开始训练` 在准备阶段会显示 `正在准备训练…`。训练时长取决于设备、数据量与 Epochs；界面给的 `~N秒/epoch（粗略估计）` **只是粗略估计**，不要把它当成完成时间承诺。

### 6.3 训练中能做什么

训练期间底部训练栏换成运行控制，按钮是：`恢复`、`暂停`、`停止`（点击停止后显示 `正在停止…`）。曲线与日志在右侧「**训练监控**」面板。

### 6.4 训练结束后

结束或中断后底部会出现 `清除运行态提示`：它会清除当前结果视图、会话指标与进度等运行态，不只是删提示文字；网络结构与已留档的 Attempt 证据不因此删除。原始文本日志保留到下一次训练开始；历史曲线需在当前课题的留档中查看。满足重跑条件时还会给出 `重新开始训练`。

### 6.5 用 GPU 还是 CPU

「设备」面板标题是 `设备选择`，顶部会显示训练运行时信息（运行时来源、Python 版本、PyTorch 版本、CUDA 状态），下方是设备列表。

规则（按当前实现）：

- 只有当**当前选中的是 NVIDIA 独显**且**运行时自检报告 CUDA 可用**时，训练才以 CUDA 提交；否则以 CPU 提交。
- CUDA 尚未确认为可用的显卡条目会显示 `训练器尚未确认 CUDA 可用`，颜色变暗且**点不动**；CPU 条目始终可选。
- 如果你已经选中 CUDA 设备，但运行时不再报告 CUDA 可用，本次训练**不会启动**，并给出：
  > 所选 CUDA 设备已不可用。为避免 Attempt 留档与实际执行设备不一致，本次训练未启动；请重新检测运行时并选择 CPU 后重试。

  这是有意设计——宁可这次不跑，也不让档案里写的设备和真正执行的设备不一致。

## 7. 推理

在右侧「**推理**」面板。

- 图像分类：先在模型卡片列表里**选中一个已完成的真实训练产物**，再 `📷 选择图片`，然后 `🚀 开始预测`。结果含 `置信度: …%` 与 `Top-5 概率分布`。
- CSV 回归：按钮文字变成 `🚀 计算回归预测值`，输入需按训练时的特征顺序给原始数值（标准化参数复用训练集的）。
- 没有可用产物时显示 `暂无可用模型`；没选卡片时会提示 `👆 请先选择一个模型卡片，再进行预测`。
- 浏览器演示模式（`npm run dev`）**不会产生模型或权重**，所以这条路拿不到可推理的模型。

界面所称“置信度/概率”是本次模型的分类输出，不等于经过校准的正确概率，更不能证明泛化。若用了训练集里的图片演示，必须注明来源：这只验证推理链路，不是独立测试。

## 8. 导出

导出分两个入口，别混淆：

**右侧「导出」面板** —— 与当前网络/Attempt 相关的产物：

- `导出 PyTorch 代码`、`导出 Keras 代码`（不需要训练过也能导，只含结构）
- `PyTorch 权重 (.pth)`、`完整模型 (.pt)`（序列化结构+权重）、`NumPy 权重 (.npz)`。完整模型的外部加载受 Python 类定义、依赖版本与加载安全策略影响，不承诺换一台机器直接 `torch.load` 即可运行；不要加载来源不明的模型文件。
- `导出训练日志 (.txt)`
- `导出实验复现包`（代码 + 原始权重 + 预处理 + 哈希；外部重跑单独留档）

这些按钮是**门控**的：条件不满足时禁用，鼠标悬停的 title 会说明原因（例如 `请先完成当前网络的真实训练并确认权重保存成功`；浏览器演示模式下导出训练日志会说明 `浏览器演示指标不可作为真实实验数据导出`）。几个会拒绝生成并给出原文的场景：

- `实验复现包必须绑定已完成的受控 Attempt；仅导出网络代码请使用下方 PyTorch/Keras 代码导出。`
- `该 Attempt 缺少原始权重或冻结预处理协议，不能生成可核验的复现包。`
- `独立实验包当前仅支持 MNIST / CIFAR-10；自定义数据集请导出模型代码并自行接入数据加载。`
- `该历史配置没有独立验证集，导出脚本将触碰封存测试集；已拒绝生成伪复现实验包。` ← 这条是**保护封存测试集**，不是 Bug
- `当前网络没有可用的 PyTorch 权重产物` / `当前训练没有成功生成 NumPy 权重`

**右侧「课题」面板**里的 `导出 Study 报告`：审计链未通过完整性校验时会弹出降级确认 `审计链未通过校验，仍然导出？`，确认后报告**强制带"档案不完整"标记**；等待确认期间切换或归档课题，这次待确认导出会作废。

导出是**单向**的：导出的证据保留来源与可信等级标签；在外部改过再重跑的结果，不会继承受控执行身份。

## 9. 三种容易"卡住"的情况

### 9.1 我已经有结构了，点了经典模型会发生什么？

**追加，不是替换。** 预设层会加在你现有积木栈顶部，原有层保持不变。若不想追加，添加前先备份，再 `🗑️ 清除`（并确认）。已经误追加时，可逐层删除新增部分，或从已保存的工程恢复；本文不假定存在“一键撤销”。「+ 添加」不会替你删东西。

### 9.2 课题（Study）和我当前的配置不一致

「课题」面板顶部有一个活动课题下拉，第一项是 `自由训练（自动草稿课题）`。

- 选它 = **快速路径**：面板空状态写明
  > 当前为快速路径：无活动 Study。下一次训练会自动进入按可比性键分组的草稿课题；也可以在上方新建一个有明确问题的课题。
- 选了一个具体课题 = 这次训练会挂到该课题的证据链下。课题的**数据与划分契约是创建时的快照**，其中包含 `严格可比资格` 判定。
- **训练准入是另一道门**：当前数据、切分或预处理与活动 Study 不符时，运行时会拒绝训练并提示 `当前数据、切分或预处理与活动 Study 不一致；请切回匹配配置或新建 Study`。非严格对比不是绕过这道门的办法。
- **对比展示**：已有记录的可比性键不同时，默认不叠加。若当前课题中确有可选的异组记录，须确认 `确认进行非严格对比？`，审计事件成功持久化后才允许带 `非严格可比` 水印展示；留痕限定精确 Attempt 集合。Study 报告列出越界记录与适用范围，不能把它解释成所有实验永久失去严格资格。
- 处理建议：**换数据、换切分口径请新建课题**，不要指望旧课题接纳不可比的结果。新手引导不会替你切换课题。

### 9.3 审计链相关的红条 / 主张无法冻结

主张（Claim）的冻结与解封必须写入**只追加审计链**。有两种不同的状态，别混为一谈：

**① 环境根本写不了审计（浏览器模式，或后端未就绪）**

主张区显示 `档案持久化不可用`，原文：

> 当前环境无法写入只追加审计链（浏览器模式或后端未就绪）；冻结与解封必须留痕，因此已失败关闭。这不是健康状态，也不提供越界入口。

此时 `冻结主张` 按钮禁用，也没有“跳过审计继续”的入口。审计不可写本身不禁止编辑草稿，但 `保存草稿` 还要求候选可合法绑定、其他操作条件满足；无候选时它也可能禁用。即使草稿保存在本地，也不等于写入了只追加审计。课题审计区会说明浏览器无法写入桌面审计；要演示冻结/解封，请改用桌面运行时，不在浏览器里绕过。

**② 桌面端审计状态与事件快照不一致**

显示 `只追加审计链异常，解封入口已关闭`，并提供 `修复并重新校验审计链` 按钮。这是**允许修复**的状态，与①不同。

另外还有一种合法锁定：候选已被评估主张引用时，面板显示

> 当前候选已被评估主张引用，不能撤回或更换。需要验证其他权重时请新建 Study。

课题的 `归档不是物理删除；仍有运行中或暂停的 Attempt 时，运行时将拒绝归档。`

## 10. 常见问题

**Q：我第一次打开为什么没反应/很慢？**
桌面端启动要自检内置训练运行时。请等待自检结束；确认你是**完整解压**后从解压目录启动 EXE，而不是只拷了 EXE。

**Q：提示"训练运行时不可用"怎么办？**
到右侧「设备」面板点重新检测。便携包用户请确认整个目录（含 `sidecars`）完整、磁盘空间足够、没有被安全软件隔离训练器进程。开发模式用户请确认 `npm run tauri dev`（不是 `npm run dev`），并检查 `NEUROBRICKS_PYTHON` 指向的环境是否真的装了 PyTorch。

**Q：为什么训练曲线在浏览器里也在动？**
那是演示模式的**模拟数据**，不会生成模型或权重，也不能用来支撑任何结论。

**Q：GPU 用不了，能不能"自动降级"到 CPU？**
不要这样理解。实际行为是：设备选择决定了提交给训练器的设备，只有当前选中的 NVIDIA 独显且自检 CUDA 可用时才用 GPU，否则走 CPU；而如果你选中的 CUDA 设备在启动瞬间已不可用，训练会**拒绝启动**并解释原因（见 6.5）。CPU 通常明显慢于 GPU。

**Q：训练要多久？一定会在五分钟内完成吗？**
不会做这种承诺。耗时取决于设备、数据量、Epochs 与 Batch；界面上的 `~N秒/epoch（粗略估计）` 只是估计。

**Q：跑出来的准确率能说明我的模型好吗？**
单次结果不足以说明稳定性。请看对比区的方差资格徽章：单 seed 会显示 `未验证方差（单 seed）`，并明确写 *不能据此声称差异显著、稳定或可靠*。多 seed 未配对也不自动等于方差已验证。

**Q：Excel 能用吗？**
不能训练。当前可信训练边界只支持 MNIST / CIFAR-10、图像文件夹和 CSV。请先转成 CSV。

**Q：切换数据集后形状报红，是不是程序坏了？**
不一定是程序故障。选中积木后在右栏底部 `校验结果` 与训练前检查里读期望/实际及建议。数据集面板对**现有网络**的适配需要确认；而添加**新的经典模型预设**会按当前数据集适配后直接追加，不是同一个确认流程。请勿把重复添加预设当作修复现有结构。

**Q：为什么清空场景、归档课题、冻结或解封要我确认？**
这些高风险入口有各自的确认流程，解封还涉及不可逆的独立验证资格。并非所有删除动作都有确认，例如 `Backspace` 会直接删除选中积木；编辑前先备份，不要依赖不存在的保护框。

**Q：反馈问题该怎么写？**
使用 `EDU-编号 + 构建标识 + 点击步骤 + 实际表现 + 预期表现 + 截图/错误原文`；旧包的旧清单才用 APP 编号。界面文字与本文不一致时先核对第 0 节，但不要忽略真实功能故障。
