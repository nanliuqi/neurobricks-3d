# 02 课堂与提交演示脚本

> 用途：**提交作品时的现场演示**（主脚本约 10 分钟），外加一份**简短的 45 分钟课堂提纲**。
> 本文是脚本，不是功能说明书；界面文字以当前源码为准，运行方式与环境前提见[快速上手与常见问题](01-快速上手与常见问题.md)。以下时间均为演示安排目标，不是运行性能承诺。

## 0. 三条前置纪律

1. **演示用的"故意错误"必须放在独立演示工程里。** 不要拿自己正在积累证据的正式课题做破坏性演示。
2. **预生成的结果必须现场说明。** 如果为了控制时间使用上一次已完成的运行留档，开口就要讲清"这是刚才/上一次真实跑完并留档的结果，不是此刻现场训练的"。**绝不把预生成结果冒充现场训练。**
3. **本脚本不演示主张冻结与解封。** 一次解封会**永久消耗这份封存测试集的一次独立验证资格**（界面原文：*解封许可一旦通过只追加审计并开始 eval-only，就会永久消耗这份测试集的一次独立验证资格。取消不会访问封存集。*）。课堂与提交演示都不该为"效果"花掉它，也不要为了让金标好看而临时编造独立性声明。

版本提醒：2026-10-13 那份便携测试包**不含**帮助面板里的新手引导；如果演示用旧包，请不要提"引导"，或者先重打包。真实训练需要桌面运行时（`npm run tauri dev` 或便携应用）；`npm run dev` 的曲线是**模拟数据**，不能当真实训练演示。

## 1. 演示前准备（提前完成，以试跑结果决定预留时间）

| 兜底 | 提前在同机跑通一次；若那一次在演示时长内跑不完，就改用"已留档的真实运行"并按第 0 节第 2 条说明 | — |

## 2. 十分钟提交演示主脚本

### 段 1 · 结构识别与形状错误修复（0:00 – 3:00）

**操作**

1. 展示 3D 场景：说明每块积木是一层，连接线是张量流的走向。
2. 确认是独立演示工程且场景为空；有需保留结构先保存，再走 `🗑️ 清除` 确认流程。展开「经典模型」→ 点 LeNet-5 的 `+ 添加`，只点一次。
3. 点选一块卷积积木 →「参数」看通道数与核大小；用 `↑↓` 切换选中、`Escape` 取消选择。这里不实际换位或删除，避免破坏稍后训练的网络；这些操作留到独立的人工验收场景。
4. **制造真正的层间形状错误**：选中第一个 Linear，记录当前 `inFeatures (输入特征)` 的有效值，再改为“原值 + 1”。不要改最后一层的 `outFeatures` 来冒充层间错误：改类别数属于数据任务契约错误，是另一种检查。
5. 点 `🚀 开始训练`，让"训练前检查"自己把问题讲出来。
6. **修复**：把该层 `inFeatures` 改回记录的原值，确认其余结构未改、训练前检查无阻断，再点 `🚀 开始训练`。

**讲解要点**

- 形状是**逐层推导**的；参数面板展示该层状态，期望/实际值与修复建议在右栏底部 `校验结果` 及训练前检查详情中，不要指着不存在的参数面板对比区讲解。
- 阻断发生时**训练根本没有启动**。本例应触发 `网络结构存在形状错误`，详情指向 Linear 输入特征与上游不匹配；另一个 `输出层与数据任务不匹配` 检查回答的是输出类别数是否匹配数据，并非同一种错误。
- 「+ 添加」预设是**追加**语义：不会清空、不会替换你已有的积木栈。想干净起步要先走 `🗑️ 清除` 的确认流程。
- 添加预设时它会按当前数据集自动适配输入形状、卷积通道数与全连接特征数；这也是为什么"先选数据集再搭结构"更省事。

**预期表现**

改坏之后：训练不启动，检查面板给出阻断项，底部按钮不会进入进度视图。
改回来之后：阻断项消失，连接指示回到正常（不再标红），`🚀 开始训练` 变成 `正在准备训练…` 并进入训练。

**出错后的安全处理**

- 如果改错的是**别的层**、越改越乱：不要现场反复试探结构，直接 `🗑️ 清除` → 确认 → 重新 `+ 添加` LeNet-5（这一步删的是演示工程的结构，删之前口头说明"这个场景里没有正式资产"）。
- 如果误删或换位导致结构断裂：从已保存工程恢复，或在确认仅含演示资产后清空，再添加一次预设。**不要在残缺网络上再次追加整套预设**。
- 如果检查面板出现的是 `正在检查训练运行环境`：这是自检没结束，等它完成再继续，不要重复点开始训练。

### 段 2 · 真实训练、曲线与推理（3:00 – 7:00）

**操作**

1. 训练启动后，右侧打开「训练监控」：进度、日志、Loss/Accuracy 曲线。
2. 演示一次运行控制：`暂停` → `恢复`（顺带说明 `停止` 会显示 `正在停止…`）。
3. 等本次训练完成；结束后底部会出现 `清除运行态提示`，满足重跑条件时给出 `重新开始训练`。
4. 右侧打开「推理」面板 → 选中刚生成的模型卡片 → `📷 选择图片` → `🚀 开始预测`。
5. 看 `置信度: …%` 与 `Top-5 概率分布`，说明它们是模型输出而非已校准的正确概率；用训练样本演示不能证明泛化。

**讲解要点**

- 训练是**真实 PyTorch 进程**在跑，界面只是执行与留档的窗口。设备与耗时如实说明：*耗时取决于设备与数据量，不承诺五分钟内一定完成*，界面上的 `~N秒/epoch（粗略估计）` 只是粗略估计。
- 至少两个有效 epoch 才连成趋势线；单个点只能读这一轮数值。近值重合先看数值表，若切换局部观察范围，必须保留放大声明；不加抖动、不把视觉差异讲成统计显著。
- 暂停/恢复/停止是受控执行的一部分，停止后这次 Attempt 的留档状态由运行时决定，不靠界面文字伪装完成。
- 推理只复用**这次训练产物**；`暂无可用模型` 是"还没有可推理的真实产物"，不是加载失败。

**预期表现**

多个 epoch 的曲线随训练推进（单 epoch 仅一个点）；日志滚动；完成后模型卡片出现在推理面板；预测给出分类输出与 Top-5 列表。

**出错后的安全处理**

- **现场训练时间不够**：诚实说明"这次先让它继续跑，我用上一次真实完成的留档来看推理"，并明确标注那是**留档结果**。不要切到 `npm run dev` 的模拟曲线救场——那是最容易被识破也最伤信任的做法。
- **推理面板显示 `暂无可用模型`**：说明本次运行没有产出可推理的真实权重（例如被 `停止`、或还在跑、或处于浏览器演示模式）。处理：等它真正完成，或改用已完成的真实模型卡片。
- **中途报错**：右栏底部常驻的 `校验结果` 区会列出结构与数据契约错误，训练本身的原因保留在训练监控/训练前检查里。现场只做**读错误**这件事：念出错误原文，说明下一步去哪里查，不现场改配置改到"看起来过了"为止。
- 若训练时报 `所选 CUDA 设备已不可用…请重新检测运行时并选择 CPU 后重试`：照提示在「设备」面板重检并改选 CPU，同时向观众解释"宁可这次不跑，也不让档案里的设备和真正跑的设备不一致"——这本身就是一次好的讲解素材。

### 段 3 · 严格对比与"可信结论"的边界（7:00 – 9:30）

**操作**

1. 右侧打开「课题」面板，依次指向四块内容：`Study 总览` → `数据与划分契约（创建时快照）`（含 `严格可比资格`）→ `预算与使用量` → `Experiment 与 Attempt`。
2. 展开 `证据对比与主张` 区域，看「严格实验对比」的分组结果：`严格可比组 1`、`孤立结果（元数据缺失、指标不完整或未验证）`、`已完成但执行不可信（不得进入严格对比）`。
3. 勾选 2 个 Attempt，选定 `共同指标（多条曲线必须同一口径）`，看曲线与最终指标表。
4. 展示 `未验证方差（单 seed）` 徽章及其说明文字。
5. （**只讲不点**）指一下主张区域，说明金标裁决需要什么条件、为什么这里今天不动它。

**讲解要点**

- 面板定义：*默认按数据、切分、任务、预处理与指标语义分组；结构/超参/轮数差异不阻止比较*。**严格可比**说明这些比较条件一致，不证明改动具有因果效果，也不是“模型长得一样”。归因还需要对照消融及配对证据，不能从任意两条曲线直接推出。
- 三条边界必须讲出来：
  1. **执行可信 ≠ 结论可信**：受控管线之外完成的记录被单独列出并禁止进入严格对比（悬停说明就是 `受控管线之外的完成结果，不能作为严格对比证据`）。
  2. **未完成的部分曲线只做排障**：*仅用于故障排查与恢复判断；不进入严格完成组、不参与候选排名、不生成最终性能结论，也不因曲线看起来完整而视为已完成。*
  3. **非严格对比必须显式确认**，并且**强制水印会进导出报告**（`确认进行非严格对比？` → `非严格可比`）。如果确实要展示，就大方让水印出现在屏幕上。
- **单 seed 不能讲成"稳定提升"**。当前对比只覆盖一次运行，界面明确写 *不能据此声称差异显著、稳定或可靠*；未配对的多 seed 也不代表方差已验证。演示时把这句话念出来。
- 裁决是三值的：`PASS` / `FAIL` / `INCONCLUSIVE`，用区间边界给出，不是挑一个最好看的数字；`INCONCLUSIVE` 的含义是证据不足，不是"效果差不多"。

**预期表现**

同一课题的可比记录进入严格组；不可信完成记录单独禁用；孤立结果另列，但并非一律不可勾选，也不因此获得严格资格。指标无共同口径时会有相应提示；少于两条不构成曲线对比，不把缺少第二条导致的空图误判成指标丢失。真实窗口的布局与提示仍需试跑。

**出错后的安全处理**

- **分组全是"孤立结果"**：这是元数据/指标语义不完整导致的失败关闭，处理办法是回看契约区说明并承认"这批记录不支持严格结论"，**不要**为了画面好看去点非严格确认（那会写入审计并加水印，观众会看到）。
- **没有第二个 Attempt 可比**：改讲“证据结构”，不讲“谁更好”。严格曲线对比首先需要第二条完整、同口径的受控记录；多 seed/配对检验解决方差问题，封存集解决预注册主张的独立验证问题。后两者不是显示两条严格可比曲线的前置条件，三件事不要混为一谈。
- **误点了非严格对比确认**：如实说明已留痕、曲线与导出报告将带 `非严格可比` 水印，并继续用带水印的画面讲解——**不要**假装它没发生，也不要反复点取消掩盖。
- **不小心点到解封/冻结相关入口**：取消不会访问封存集；若已经通过许可进入 eval-only，则那次独立验证资格已消耗，现场要如实说明并停止后续主张演示。

### 段 4 · 收尾（9:30 – 10:00）

**操作与讲法**：右侧「导出」面板只展示**当前真实的门控状态**，不实际导出。若已训练完成，有些按钮理应启用，不要为了讲门控假称它们禁用；仅对实际禁用项读原因。收尾说明：工具帮助追溯证据，并明确拒绝哪些过度结论；可复现仍受数据、环境和协议范围限制，不承诺跨机器数值完全相同。

## 3. 45 分钟课堂提纲（简版，不展开完整教案）

| 时间 | 环节 | 要点 | 学生动作 |
| --- | --- | --- | --- |
| 0–5 | 定位 | 小数据、单机单卡、监督式学习；明确不做检测/分割/多标签/LLM 微调 | 听 |
| 5–12 | 结构与形状 | 积木=层，连接线=张量流；新手引导与清空确认保护 | 读引导、辨认层卡片，不改结构 |
| 12–20 | 数据与适配 | 内置图像数据、自定义图片、CSV 显式目标列；Excel 边界 | 先选数据集，空场景只添加一次 LeNet-5；追加语义口头解释，不把两套结构叠起来训练 |
| 20–30 | 训练与监控 | 演示 Epochs=2–3，若只跑 1 轮则不讲趋势；运行控制与训练前检查 | 跑一次；来得及才暂停/恢复，没触发就如实说明 |
| 30–38 | 推理与失败 | 模型卡片、`📷 选择图片`、Top-5；`暂无可用模型` 的含义 | 预测一张图；说出一次失败原因 |
| 38–44 | 证据与边界 | 严格可比组 vs 非严格水印；单 seed 未验证方差；PASS/FAIL/INCONCLUSIVE；封存集资格只消耗一次 | 只看不点解封 |
| 44–45 | 收束 | 结论必须能追溯到数据、切分、配置与设备 | 一句话复述边界 |

课堂纪律与第 2 节相同：**故意错误放独立演示工程**、**不消耗封存测试集**、**不承诺时长与精度**。

## 4. 演示与课堂里不能出现的说法

| 不能说 | 为什么 | 可以怎么说 |
| --- | --- | --- |
| "特征图可视化""Feature Map 查看" | 该能力在路线图上**尚未实现**，当前界面没有这个入口 | "这是路线图上的下一项，现在还没有" |
| "支持 Fashion-MNIST" | 内置数据集只有 **MNIST / CIFAR-10**；只有某个预设的说明文字里提到 Fashion-MNIST，那不是数据入口 | "可以用图像文件夹方式自备数据，但要按自定义数据集的规则走" |
| "有教学模式/专家模式双切换" | 当前**没有**这个模式开关 | "参数默认收起在 `⚙ 高级` 里" |
| "跑完准确率 X% 说明这个网络更好" | 单 seed、未做独立验证 | "这一次的结果是 X%，还不能说明差异显著或稳定" |
| "浏览器里曲线也在跑，就代表训练过了" | 浏览器演示模式是模拟数据，不生成模型或权重 | "要看真实执行，得用桌面端" |
| "解封看一下金标效果" | 一次解封永久消耗一次独立验证资格 | "今天不解封；先讲金标需要哪些前置条件" |
| "五分钟一定能训练完" | 耗时取决于设备与数据量 | "课堂设 Epochs=1，实际耗时看机器" |
| "导出后我们在外部改一改再跑，结果一样可信" | 外部重跑不继承受控执行身份 | "导出是单向证据留档，外部重跑要单独留档" |

## 5. 本脚本尚未验证的项目

1. **现场时长**：未在演示用机器上实测"1–3 epoch MNIST + 推理"是否落在 10 分钟窗口内；请按第 1 节提前试跑并准备留档兜底。
2. **错误提示排版与恢复路径**：形状错误示例已按 Linear.inFeatures 的检查逻辑核对，但真实窗口的提示截断、连接线表现与参数恢复仍需试跑；输出类别数错误是单独的数据契约检查。
